# V362 预算路径历史锚点独立审计预冻结记录

## 审计问题

V361 的唯一失败项是：在预算 $\delta=0.01$ 时，PCHP 的绝对 MAE 未通过 V327 历史锚点检查。初步诊断发现，V361 读取的是 V327 报告 JSON 中被截断为 10 位小数的数值，但比较容差仍为 $10^{-12}$。因此，需要独立判断该失败究竟是科学结果不一致，还是序列化精度导致的审计假阴性。

## 冻结边界

本审计不重新估计任何模型、不重新运行 bootstrap、不修改 V361 文件，也不改变 V361 的估计量、预算网格、选择规则或门槛。允许执行的操作只有：验证输入哈希；将 V361 在 $\delta=0.01$ 时的结果与 V327 的高精度 CSV 比较；逐域比较 12 个完整数据域；将超参数选择与 V326 高精度 CSV 比较；量化 V327 JSON 的精度损失；确认 V361 的非锚点科学门槛与主结果保持不变。

## 权威锚点

- 汇总指标：`nested_outer_summary_v327.csv`
- 逐域指标：`nested_outer_domain_metrics_v327.csv`
- 超参数选择：`nested_alpha_selections_v326.csv`

比较继续使用 V361 原定的绝对容差 $10^{-12}$，相对容差为 0。改变的不是门槛，而是把被截断的展示层 JSON 替换为生成它的高精度权威 CSV。

## 判定规则

只有当文件哈希、操作性诊断、高精度汇总锚点、全部逐域锚点、超参数选择锚点以及 V361 的非锚点科学门槛全部通过时，才把该失败归类为“JSON 精度导致的操作性假阴性”。通过后也只能保留 V361 为“协议锁定的回顾性敏感性证据”；不得把它升级为冻结外部确认，也不得回写或删除 V361 的原始 `NARROW` 记录。
