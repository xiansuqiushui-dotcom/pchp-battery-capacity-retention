`manifest_v368.json` is generated by `make_manifest_v368.py`. It records the SHA-256 digest and byte length of every tracked package file except itself, the current V368 verification receipt, Python caches, and regenerated files under `figures/` directories.

The V368 verifier pins the authoritative hashes inherited from the V342/V365 scientific-code and novelty closure, the pre-frozen V366 loss-geometry artifacts, the V368--V373 manuscript and reviewer-risk audits, the rejected V374 bounded-recovery experiment, the retained V375 untuned-backbone portability audit, the V376 closest-neighbor positioning audit, the V377 method-elevation and operator-stability audit, and the V378 finite-sample statistical stress audit. It preserves the frozen V374 property-test result and failed empirical gates, independently recomputes the V375 domain statistics and deterministic certificates from the included record-level predictions, enforces the design-independence external-confirmation boundary, replays the V377 prefix-nonexpansiveness validator, exhaustively replays all $2^{12}=4{,}096$ V378 sign assignments for three domain-level effects, reruns the inherited deterministic validators, and can regenerate all manuscript figures and the graphical-abstract PNG.

A newly generated manifest therefore cannot legitimize a modified scientific implementation, substituted result report, rescued failed V374 gate, broadened V375 portability claim, an absolute-lineage external-confirmation requirement, a reinterpretation of V377 stability as accuracy or physical safety, a reinterpretation of the V378 mean effect as universal or majority-probability dominance, or an unreviewed submission asset.

Run the generator only after an intentional package update:

```powershell
python make_manifest_v368.py
python verify_reproducibility_v368.py --regenerate-figures --write-receipt
```

The copied V341/V342/V365/V366/V367 manifests and receipts are retained as historical records; current package verification is controlled by the V368 files above.
