# V390 最终完成审计

## 论文主线

现实问题是：车队在参考容量尚不可得时仍需更新电池健康记录，而无标签部署需要同时控制逐次更新可能造成的预测损害并禁止未来数据改写既有估计。PCHP 以受保护的前缀因果状态为参照，将候选预测投影到递归可行的损害预算区间中。核心贡献是这一可执行的部署约束，而不是泛称所有跨域方法均无效。

## V390 关闭的问题

1. 将摘要中的普遍否定改为有力且有边界的部署缺口表述，中英文同步。
2. 使投稿元数据与已经公开的 GitHub 代码状态一致。
3. 将单调性消融报告中的非标准 `NaN` 改为严格 JSON 的 `null`，并在写出端禁止非标准常量。
4. 用兼容导入恢复标准核心测试发现，40 项核心测试全部通过，且未改动 V368 哈希固定实现。
5. 为所有 V380--V387 执行入口建立可执行复现预检，不再把有意缺少第三方输入的历史脚本暗示为可直接运行。
6. 新增验证型公共 API，对缺失或空电芯标识失败闭合，并以测试证明合法输入与冻结算子逐元素一致。
7. 为外部预测的同名义循环记录建立 9,712 条唯一身份账本，不改动原预测表与估计量。
8. 将修订跟踪器中的本机绝对路径改为仓库相对路径，并为中文作图增加 Windows、Linux 与 macOS 字体候选。
9. 补全 SAFER 的 AAAI 页码，保留两条确实无传统页码的 ICLR 记录。
10. 明确 PDF 冻结字节与本地内容级重编译的区别。

## 最可能的三项审稿意见

1. “方法创新是否只是已有投影的重新命名”：以逐次损害约束、递归可行性、前缀不可回写及其电池运维场景的统一合同回应；保留有限文献检索边界，不作普遍优先权宣称。
2. “外部确认是否真正独立”：以方法、比较器、估计量和决策规则未受该结果影响的冻结设计回应，同时不称为新采集实验室证据。
3. “公开代码是否能完整重训”：以直接账本重放和提供方依赖的完整重算分层回应；不通过再分发无授权数据来制造表面上的一键运行。
